8. Stage 2G — Auto Loader

Concepts + all 5 checks passed 2026-07-16 · Lab run 2026-07-17 · Added to the plan mid-flight, not in the original

Covered and verified

  • The cloudFiles model — a streaming source whose checkpoint (RocksDB) tracks which files have been processed → incremental, exactly-once. Contrast: a plain read reprocesses everything.
  • Auto Loader vs COPY INTO — COPY INTO: SQL, thousands of files, scheduled and idempotent. Auto Loader: streaming, millions of files, continuous, with schema evolution.
  • Two discovery modes — directory listing (default, zero setup, expensive at scale) vs file notification (SNS+SQS / EventGrid / PubSub, scales, needs cloud permissions).
  • Schema inference + evolution — inferColumnTypes; schemaEvolutionMode=addNewColumns (default) means fail → update → restart captures the column; _rescued_data catches the unmatched; schemaHints fixes wrong guesses (e.g. zip inferred as int).
  • Two "format" options, which trips people up — .format("cloudFiles") and cloudFiles.format = "json". Plus schemaLocation, checkpointLocation, and the availableNow trigger. Also covered .start() vs .toTable().

Hands-on — incremental ingest lab (2026-07-17)

databricks_exercises.py §8. Dropped orders_1/2/3.json into /Volumes/workspace/autoloader_lab/landing.
  • Incremental pickup proven via DESCRIBE HISTORY: v1 numOutputRows=2, v2 numOutputRows=1. One, not three — both files were still sitting in the directory, so writing 1 row proves file 1 was skipped because the checkpoint remembered it. That's the whole point of the lab.
  • Schema evolution: got DELTA_METADATA_MISMATCH (write side), not UnknownFieldException (read side) → ALTER TABLE ADD COLUMN region → rerun → 4 rows, region='us-west' on order 4, NULL on 1–3.
★ Your best catch of the whole track — worth being able to say out loud in an interview.

A cloudFiles → Delta pipeline has two independent schema guards, and evolving one does nothing for the other:
  • Read side → cloudFiles.schemaEvolutionMode, state stored in schemaLocation.
  • Write side → mergeSchema, state stored in the table's _delta_log.
Auto Loader evolved its read schema fine; the Delta sink rejected the wider DataFrame via schema enforcement (2C). DeltaSink.updateMetadata in the stack trace is the tell that the failure is on the write.

The normal fix is .option("mergeSchema","true") — but on UC standard access mode, Table ACLs block automatic schema migration, so you must ALTER TABLE … ADD COLUMN explicitly. That governance-vs-convenience trade-off is a genuinely Staff-level observation.
Two of my errors you caught by actually running it (recorded because it's a good habit to keep): numFilesInputted is not a real progress key — it's numInputRows, and Auto Loader adds numFilesOutstanding/numBytesOutstanding under sources[0].metrics. And chaining .awaitTermination() onto .toTable() throws away the query handle. Also clarified: display() and dbutils.fs.put do not insert into tables — only the stream cell does.
