4. Frameworks to have reflexive by Sep 4

4.1 The metric-change diagnostic (“DAU dropped 5% — why?”)

The most-asked product-sense shape at Meta. Never start guessing causes. Run this order out loud:

  1. Clarify the metric & the change. What exactly is DAU here — logged-in? any-surface? What's the magnitude, over what window, is it a step-drop or a gradual slide?
  2. Is it real? Logging/instrumentation change, pipeline failure, bot filtering change, definition change, duplicate or missing data. Always ask this first — half of real drops are not real.
  3. Is it expected? Seasonality, day-of-week, holiday, school term, prior-year comparison.
  4. Segment. Cut by platform/OS, country, app version, new vs existing users, tenure cohort, device. Find where the drop concentrates — a drop that is uniform across all cuts means something different from one concentrated in Android.
  5. Internal causes. Product launches, A/B test rollouts, ranking model changes, latency/crash regressions.
  6. External causes. Competitor launch, news event, outage, regulation, app-store change.
  7. Decompose the metric. DAU = new + retained + resurrected − churned. Which term moved? This converts a vague question into a countable one.
  8. State next step and what data would confirm it.
Say step 7 out loud at some point in every one of these. Metric decomposition is the single move that separates a DS answer from an analyst answer.

4.2 Goal / success-metric definition (“How would you measure success of X?”)

  1. What is the product trying to do? State the user value in one sentence.
  2. One North Star — the metric that only moves if real value was delivered.
  3. Supporting metrics — the drivers that decompose the North Star.
  4. Guardrail / counter-metrics — what could this break? (time spent elsewhere, report rate, latency, ad revenue, sessions per user). Meta weights this heavily; a candidate who names no counter-metric is scored down.
  5. Ecosystem metrics — effect on the other side of the market (creators vs viewers, buyers vs sellers).
  6. Say the tradeoff explicitly: “I'd ship on North Star X even at a small cost to Y, because…”

4.3 A/B test design

  1. Hypothesis — stated as a falsifiable sentence with a direction and a metric.
  2. Unit of randomisation — user / session / device / cluster. Ask whether there are network effects (Facebook/Instagram almost always have them → user-level randomisation leaks; you may need cluster or geo-based).
  3. Primary metric, secondary, guardrails.
  4. Power & sizing — MDE, α = 0.05, power = 0.8, baseline rate and variance → sample size → runtime. You don't need the exact formula, but you must say these five words.
  5. Duration — at least one full weekly cycle; long enough to clear novelty and primacy effects.
  6. Validity threats — sample ratio mismatch, interference/spillover, selection bias, seasonality, multiple-testing inflation, peeking.
  7. Read-out & decision rule — decided before the test, not after.

4.4 Stats cheat sheet (the whole in-scope syllabus)

ConceptWhat you must be able to say in 30 seconds
Mean / median / mode / percentilesWhich to use on skewed real-world data (time-spent, revenue → median/percentiles, never mean alone).
Binomialn independent trials, fixed p. Mean = np, variance = np(1−p). Use for conversion/click/completion counts.
Normal68/95/99.7. Why sample means go normal even when the data isn't.
Law of Large NumbersSample mean → true mean as n grows. Why small A/B cells swing wildly.
Central Limit TheoremThe sampling distribution of the mean is normal regardless of the population's shape, given enough n. This is why we can t-test skewed metrics.
Conditional probability / BayesP(A|B) = P(B|A)P(A)/P(B). Rehearse the false-positive/base-rate classic — Meta asks this shape (“model flags a user as likely to convert; what's P(actually converts)?”).
Hypothesis testingH₀ / H₁, test statistic, p-value = P(data this extreme | H₀ true). Not the probability the hypothesis is true.
Type I / Type III = false positive = α = ship something that does nothing. II = false negative = 1−power = kill something that worked.
Confidence intervalOver repeated samples, 95% of such intervals contain the true value. Say it in a business sentence too.
PowerP(detect a real effect of size MDE). Driven by n, effect size, variance, α.
Multiple testing20 metrics at α=0.05 → ~1 false positive by chance. Bonferroni / FDR, or pre-register one primary metric.
Linear regressionWhat the coefficients mean, why correlation ≠ causation, confounders, and when you'd use regression to adjust rather than predict.
Real-world data profileHeavy right skew, zero-inflation, bots, power users dominating totals → why you cap/winsorise and report medians.

4.5 SQL patterns that actually show up (analytics flavour, not DE flavour)

  • Retention / N-day return — self-join on user with a date offset, or DATE_DIFF bucketing. Know D1/D7/D28 and rolling vs classic definitions.
  • Cohort tables — signup-week cohort × weeks-since-signup grid.
  • Funnel conversion — step counts per user, conversion between steps, drop-off rate, using conditional aggregation (COUNT(DISTINCT CASE WHEN step='x' THEN user_id END)).
  • DAU / WAU / MAU and stickiness (DAU÷MAU), rolling windows with a date spine.
  • Sessionisation — LAG on timestamp, flag gap > 30 min, cumulative sum to make session ids. Classic “no magic function” question.
  • Gaps-and-islands / consecutive days — date − ROW_NUMBER() is constant within a streak. You have failed the “why is it constant” retention check twice. Fix it: because inside a run both sides increment by 1, so the difference cannot change; a missing day skips a date but not a row number, so the difference jumps.
  • Top-N per group — ROW_NUMBER vs RANK vs DENSE_RANK, and which the wording implies.
  • Month-over-month change — LAG + the 100.0 placement to avoid integer division.
  • Churn — “no activity in the last 28 days” style definitions, anti-joins / NOT EXISTS.
  • Dedup — ROW_NUMBER() … QUALIFY, and the manual version when QUALIFY isn't allowed.
